Write a selector, get it graded live — for whether it matches, and for whether it will still match in six months.

Type a CSS selector (or an XPath starting with /) and the lab evaluates it against the real DOM: how many elements it matches, whether it hit the right one, and whether it leans on anything that tends to break.     Locator priority

    1. getByRole — what a screen reader sees. Tests a11y for free.
    2. getByLabel — form controls.
    3. getByPlaceholder — when there's no label (there should be).
    4. getByText — static copy only, never stateful text.
    5. getByTestId — your escape hatch. Stable by contract.
    6. CSS — when nothing above fits.
    7. XPath — last resort. Never absolute.

    Flake signatures

    The lab flags these automatically:

    • Generated classes — .css-1x2y3z, .sc-AbCdEf
    • Generated ids — #input-48213, #:r7:
    • Positional — :nth-child(), .nth(2)
    • Absolute XPath — /html/body/div[3]/…
    • Stateful text — "Cart (0)"
    • Matching more than one element

    The sandbox

    A deliberately mixed-quality DOM. Some elements are well-marked; others carry exactly the traps you'll meet in a real app.
