Todo List (Buggy build)

Same feature as the clean todo — but this build contains real defects.

Testing charter — Verify the behavior spec on the right. Try edge cases: empty input, whitespace, filters with 0 items, refresh, XSS-shaped payloads, the counter after various actions.

My Todos

    0 items left · Clear completed

    Behavior spec

    • Empty or whitespace-only input cannot be added.
    • User input must be rendered as text, never as HTML (no XSS).
    • Filters: All / Active / Completed — Active shows only incomplete items.
    • "X items left" reflects the current INCOMPLETE count.
    • "Clear completed" removes only completed items; active items stay.
    • State persists across refresh.

    Answer key

    1. Whitespace-only todos can be added. Entering " " creates a blank item — should be rejected.
    2. XSS: input rendered as HTML. Adding <img src=x onerror=alert(1)> executes the handler — user input must be textContent, not innerHTML.
    3. "Items left" counts total, not incomplete. The label shows all todos regardless of state.
    4. "Active" filter shows completed items too. Filter predicate is inverted / wrong.
    5. "Clear completed" removes everything. Wipes the whole list, active items included.
    6. State does not persist across refresh. Save function is a no-op; refreshing loses all todos.
