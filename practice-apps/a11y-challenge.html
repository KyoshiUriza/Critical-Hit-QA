What to look for

  • Missing form labels
  • Missing button names / non-button elements acting as buttons
  • Removed or missing focus indicators
  • Insufficient text/UI color contrast
  • Information conveyed by color only
  • Missing image alt text
  • Non-descriptive link text ("click here")
  • New-window links with no warning
  • Heading order out of sequence
  • Missing grouping (fieldset/legend) for related controls

Tools

  • Keyboard: Tab, Shift+Tab, Enter, Space, arrow keys.
  • Browser DevTools → axe DevTools extension → run scan.
  • Lighthouse → Accessibility category.
  • Screen reader: VoiceOver (macOS Cmd+F5), NVDA (Win), Narrator (Win).
  • Color contrast checker: WebAIM contrast checker.

Answer key

  1. Form inputs missing <label>. Email and Full name are plain divs above unlabeled inputs. WCAG 1.3.1, 3.3.2, 4.1.2.
  2. Required indicator uses color only. Asterisk color is nearly invisible; no text alternative ("Required"). WCAG 1.4.1, 3.3.2.
  3. Focus indicator removed. outline:none with no replacement. WCAG 2.4.7.
  4. Text contrast fails. Gray input text on light background is far below 4.5:1. WCAG 1.4.3.
  5. Button contrast fails. Light-blue text on blue background. WCAG 1.4.11.
  6. Div acting as button. .fake-btn is a div with click but no role, tabindex, or keyboard handler. WCAG 2.1.1, 4.1.2.
  7. Icon-only button lacks accessible name. The ✕ button has no aria-label or visible text. WCAG 4.1.2.
  8. Checkbox group missing <fieldset>/<legend>. Screen readers can't announce the group purpose. WCAG 1.3.1.
  9. Image missing alt text. Logo <img> has no alt attribute. WCAG 1.1.1.
  10. Non-descriptive link text. "click here" gives no context out of surrounding prose. WCAG 2.4.4.
  11. New-window link with no warning. target="_blank" with no rel="noopener" and no user-facing indication. WCAG 3.2.5, security.
  12. Heading order skips levels. h2 jumps to h5. WCAG 1.3.1.
  13. Error state uses color only. Red text, no icon, no aria-live, no role="alert". WCAG 1.4.1, 4.1.3.
