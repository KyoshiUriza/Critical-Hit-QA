Login Form (Buggy build)

Same feature as the clean login — but this build contains real defects. Your mission: find and log them all.

Intended valid credentials: demo@qa.test / Passw0rd!

Testing charter — Verify the behavior spec on the right against what the app actually does. File one bug per real defect you find. Try boundary values, invalid input, security-shaped payloads, and repeated actions before revealing the answer key at the bottom.

Sign in

Behavior spec (your oracle)

  • Email must be present and RFC-valid (require a domain with a dot).
  • Email comparison must be case-insensitive; leading/trailing whitespace trimmed.
  • Password must be present, min 8 chars.
  • Valid creds: demo@qa.test / Passw0rd!.
  • After 3 failed attempts, lock for 30 seconds. Counter resets on success.
  • "Show" button toggles password visibility both ways; label updates.
  • "Remember me" persists only the email — never the password.
  • Errors must not reveal whether an account exists.

Testable attributes

Same data-testids as the clean build: login-email, login-password, login-submit, toggle-password, remember-me, email-error, password-error, login-result.

Answer key

Test on your own first. Reveal only after you've drafted your bug list.

  1. Email regex too permissive. Accepts a@b (no dot / no TLD) as valid — should reject.
  2. Case-sensitive email comparison. Demo@qa.test with the correct password fails — email compare should be case-insensitive.
  3. Email whitespace not trimmed. "demo@qa.test " (trailing space) fails validation.
  4. Empty password bypasses validation. Submitting with the correct email and blank password shows a "Welcome" success — should require a password.
  5. Password minimum length not enforced. Any non-empty password is accepted format-wise; a 1-char password produces no error.
  6. Lockout counter not reset on successful login. Two failed attempts, then a successful login, then a failed attempt → immediately locked. Counter should reset on success.
  7. "Show" toggle is one-way. Clicking again does not hide the password or change the label back to "Show".
  8. Info-leak in error messages. Wrong password on the valid email says "Wrong password"; any other email says "No such account" — enables user enumeration.
  9. "Remember me" stores the password in localStorage under remembered_pw — should never persist the password.

Bonus practice: for each defect, write a full bug report using the Test Case Builder template — title, steps, expected vs. actual, severity/priority, evidence.
