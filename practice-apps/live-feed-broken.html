Pulse Ops Feed (buggy build)

Six defects that only exist in the gap between starting something and it finishing. Timing is the test.

The specification — Posting sends exactly one post per submission. A post that fails to save does not stay on screen claiming it sent. Search results always match what is currently in the search box. Refreshing does not duplicate items and does not touch what you are typing. The unread count equals the number of items that arrived.

Every defect here needs timing to reproduce. Click fast, type fast, and do two things at once. Doing one action at a time and waiting for it finds none of them — which is precisely why they reach production.

How to test something that only breaks when it overlaps

  1. Do two things at once, on purpose. Click submit twice. Refresh while typing. Type a query while the last one is still in flight. Almost every defect here needs exactly one overlap.
  2. Throttle the network. DevTools → Network → Slow 3G widens every window from milliseconds to seconds, which turns a race you cannot hit into one you cannot miss. This is the highest-value trick in the category.
  3. Watch the panel, not the page. Two POSTs in the Network tab is proof of a double submit; the feed showing one item is not proof it did not happen.
  4. Reload before you believe it. An optimistic UI shows you what it hopes happened. A reload shows you what was stored, and the gap between them is a whole category of defect.
  5. Say how often it reproduces. "One time in five, when I click twice inside about a second" is a report a developer can work from. "Sometimes duplicates" is not.
Names worth using in the report. Calling a defect a race condition, a stale response, a lost update or a missing idempotency guard tells a developer where to look. The fixes are well known — disable the control while in flight, tag each request and ignore responses that are not the newest, merge by id rather than appending, and check whether a field is dirty before overwriting it. Naming the fix in the report is not overstepping; it is the difference between a ticket and a conversation.
