Registration Form (Buggy build)

Same feature as the clean register — but this build's validation lies to you.

Testing charter — Push every field at its boundaries. Try mismatched passwords, edge-case ages, invalid emails, and skipping the TOS. Compare each interaction against the spec.

Create your account

Behavior spec

  • Full name: required, ≥ 2 chars, whitespace trimmed.
  • Email: required, valid format (must include TLD).
  • Age: required, integer 13–120. Under 13 = "must be 13+".
  • Country: required.
  • Password: min 8 chars; must have upper, lower, digit, symbol.
  • Confirm must match password EXACTLY.
  • Strength meter reflects actual password entropy.
  • Must accept TOS.
  • Form disables and shows success only when everything is valid.
  • No double-submit.

Answer key

  1. Full name allows 1 character. Length check uses > 0 instead of ≥ 2.
  2. Email regex too permissive. Accepts a@b (no dot / TLD).
  3. Age boundary off by one. Age 12 is accepted as ≥ 13 (uses > 12 without checking equality against 13 properly, or uses age >= 12).
  4. Country validation missing. Submitting with "Select…" still succeeds.
  5. Password complexity not enforced. Only length is checked — aaaaaaaa (8 a's) is accepted.
  6. Password strength meter always shows "Strong". Regardless of actual password.
  7. Confirm-password comparison ignores trailing whitespace. "Passw0rd!" and "Passw0rd! " are treated as matching.
  8. TOS not enforced. Form submits successfully with the checkbox unchecked.
  9. Submit button not disabled after success. Rapid double-click submits twice (would create duplicate accounts).
