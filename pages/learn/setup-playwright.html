Install Playwright and run your first test

Every other task on this site links to a page that does the thing. This one asks you to leave and set up a toolchain — so here is the whole path, with nothing assumed.

Written for someone who has never installed a developer tool. If you already have Node and a terminal you use, skip to step 3. If the word "terminal" is doing a lot of work in that sentence, start at step 1 — that is what this page is for, and needing it is not a gap in you.

1 · Open a terminal

A terminal is a window where you type commands instead of clicking. You need it because the tooling has no buttons.

  • Windows: press the Start key, type powershell, press Enter.
  • macOS: press Cmd+Space, type terminal, press Enter.
  • Linux: Ctrl+Alt+T on most desktops.

You will see a line ending in > or $. That is the prompt, waiting for you. Nothing you type here can break your computer by accident.

2 · Install Node.js

Playwright is written in JavaScript, and Node is what runs JavaScript outside a browser. Check whether you already have it:

node --version

A version number of v18 or higher means you are done — go to step 3. An error like "command not found" or "not recognized" means Node is not installed.

If you need it, download the LTS build from nodejs.org. LTS means Long Term Support — the stable one. Accept every default in the installer, then close your terminal and open a new one (it only reads your PATH at startup, which is the single most common reason people think the install failed) and run node --version again.

3 · Create the project

Make a folder for your tests and move into it. cd means "change directory".

mkdir qa-practice
cd qa-practice

Now scaffold Playwright:

npm init playwright@latest

It asks four questions. The answers that matter:

QuestionAnswerWhy
TypeScript or JavaScript?JavaScriptThis site's examples are JavaScript. You can switch later; the concepts do not change.
Name of your tests foldertests (default)Convention. Take the default.
Add a GitHub Actions workflow?YesCosts nothing now, and it is the file an interviewer likes seeing in your repo.
Install browsers?YesPlaywright ships its own browser builds so runs are reproducible. It is a few hundred MB.

This takes a few minutes and prints a lot of text. That is normal.

4 · Run the example test

The scaffold includes working tests. Run them before writing anything, so that when something breaks later you know the setup itself was fine:

npx playwright test

You should see something like 6 passed. Then open the report:

npx playwright show-report

If both worked, you have a functioning automation environment — which is a genuine milestone, and the thing most people trying to learn automation never get past.

Now try the mode you will actually live in:

npx playwright test --ui

UI mode lets you run one test, watch it step through, and see the DOM at each action. It is the single most useful command on this page.

5 · Point it at this site

The practice apps are static pages, so you can run tests against the live site with no server of your own. Create tests/login.spec.js and paste this: 

const { test, expect } = require('@playwright/test');

const APP = 'https://kyoshiuriza.github.io/Critical-Hit-QA/practice-apps/login.html';

test('valid credentials sign in', async ({ page }) => {
  await page.goto(APP);
  await page.getByTestId('login-email').fill('demo@qa.test');
  await page.getByTestId('login-password').fill('Passw0rd!');
  await page.getByTestId('login-submit').click();

  await expect(page.getByTestId('login-result')).toContainText('Welcome');
});

Run just that file:

npx playwright test login.spec.js --headed

--headed shows the browser so you can watch it happen. Once you trust it, drop the flag and it runs invisibly and faster.

That is a real automated test against a real deployed page. Next: open the Automation Lab for specs covering the other apps, and the Locators track for why every selector above is a getByTestId and not a CSS path.

When it goes wrong

These four cover most first-time failures.

What you seeWhat it meansFix
'npm' is not recognized Node is installed but this terminal does not know it yet. Close the terminal, open a new one. If it persists, reinstall Node with defaults.
Executable doesn't exist at … The browser binaries did not download. Run npx playwright install.
EACCES / permission denied You are installing somewhere your user cannot write. Work in your home folder. Do not reach for sudo npm — it causes more problems than it solves.
Test fails with TimeoutError The locator never matched. Check the selector before touching the timeout. Playwright Errors walks the whole diagnosis order.

Stuck on something not listed? That is a bug report waiting to happen — which is convenient, because writing good ones is the skill. Note what you did, what you expected, what you got, and open an issue on the repo.
