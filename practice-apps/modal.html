Modal & Confirmation Dialog

Focus trapping, ESC handling, backdrop clicks — a classic automation and a11y target.

Click a button to open the corresponding modal. When it opens, try Tab/Shift+Tab, Esc, clicking the backdrop, and each action button.

Behavior spec

  • Background is inert and dimmed while a modal is open.
  • Focus moves into the modal on open; first focusable receives focus.
  • Tab and Shift+Tab cycle only within the modal (focus trap).
  • Esc closes the modal (except destructive — requires explicit choice).
  • Backdrop click closes info; does NOT close confirm/destructive.
  • On close, focus returns to the button that opened it.
  • Modals use role="dialog" and aria-modal="true".
  • Toast confirmation appears after destructive delete succeeds.

Test ideas

  • Screen reader: is the modal title announced?
  • Try Tab past the last focusable — does it wrap?
  • Open a modal, then use browser back button — reasonable?
  • Open modal on mobile viewport — does it fit? Is it scrollable?
  • Rapid open-close-open — any state left over?
